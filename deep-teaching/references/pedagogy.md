# Pedagogy

Use this reference when you plan a lesson, sequence a course, adapt instruction, or decide whether the learner has demonstrated an objective.

## Teaching goal

Design for observable learning, not content exposure. A lesson succeeds when the learner can perform the target action under the stated conditions and can later retrieve or transfer the capability.

Use this alignment chain for each objective:

```text
learner purpose
→ prerequisite knowledge
→ observable objective
→ explanation or demonstration
→ guided practice
→ independent performance
→ retrieval or transfer evidence
→ next learning decision
```

Remove an activity that does not support an objective. Revise an objective when no activity can produce valid evidence for it.

## Establish the learning context

Determine the smallest amount of context needed to design useful instruction:

- The capability that the learner wants to gain.
- The real task or purpose that makes the capability useful.
- The learner’s prior knowledge and relevant experience.
- The prerequisites required for the immediate lesson.
- The time available and desired depth.
- The tools, language, platform, or environment involved.
- Whether the goal is conceptual, procedural, or both.
- Accessibility, delivery, grading, privacy, or offline constraints.

Infer context from the conversation when the evidence is sufficient. Ask only questions whose answers would materially change the lesson. State assumptions when you proceed without an answer.

For a course, state the learner’s purpose as a mission:

> Become able to [observable capability] so that [real purpose or context].

Use the mission to select examples, exercises, sources, and later lessons.

## Write observable objectives

Use one to three objectives for a bounded lesson. Each objective must describe:

- An observable learner action.
- The content, system, or skill involved.
- Any important condition or constraint.
- The evidence that demonstrates success.

Prefer verbs such as:

- Identify.
- Classify.
- Trace.
- Predict.
- Compare.
- Explain.
- Solve.
- Debug.
- Design.
- Implement.
- Evaluate.

Do not use `understand`, `learn`, `know`, `appreciate`, or `be familiar with` as the main verb. These verbs describe internal states that do not define assessable evidence.

### Match the objective and evidence

The assessment must require the action named by the objective.

| Objective action | Suitable evidence |
|---|---|
| Identify | Select, label, or name the relevant element in context |
| Classify | Place unfamiliar examples into categories and justify difficult cases |
| Trace | Show the sequence of states, calls, events, or transformations |
| Predict | State an outcome before execution and explain the mechanism |
| Compare | Identify consequential similarities, differences, and trade-offs |
| Explain | Give a causal or structural account in the learner’s own words |
| Debug | Locate the first consequential error, explain its effect, and correct it |
| Design | Produce an artifact that satisfies explicit constraints |
| Implement | Create a working result under the stated conditions |
| Evaluate | Apply criteria, make a judgment, and support it with evidence |

A recall question cannot establish an implementation objective. A guided imitation cannot establish independent performance. A familiar example cannot by itself establish transfer.

## Check prerequisites

A prerequisite is knowledge or skill that the lesson depends on but does not intend to teach.

Use a short prerequisite check when missing foundations would prevent progress. Ask the learner to perform the prerequisite rather than report familiarity with it.

Examples:

- Ask for the output of a small expression instead of asking whether the learner knows the syntax.
- Ask the learner to label two parts of a diagram instead of asking whether the diagram looks familiar.
- Ask the learner to perform one representative operation instead of asking for a confidence rating.

If a prerequisite is missing:

1. Identify the smallest missing unit.
2. Teach or link a short prerequisite lesson.
3. Recheck the prerequisite with a different prompt.
4. Return to the original objective only after the prerequisite is usable.

Do not treat unfamiliar terminology as proof that the learner lacks the underlying concept. Do not treat a formatting error as a conceptual failure.

## Select scope and difficulty

Teach the smallest complete unit that advances the learner’s purpose. Do not compress a complex mechanism until the explanation becomes false or misleading.

Start below the [118;1:3upoint where terminology or missing prerequisites block reasoning. Increase difficulty after the learner succeeds without excessive support. Reduce complexity, add a representation, or restore a prerequisite after repeated conceptual errors.

Use these difficulty controls:

- Number of interacting elements.
- Familiarity of the context.
- Amount of scaffolding.
- Number of decisions the learner must make.
- Availability of examples, cues, tools, and references.
- Distance between the practice context and the transfer context.
- Time pressure, if time is part of the authentic performance.

Do not add difficulty through unclear wording, irrelevant calculation, hidden assumptions, inaccessible controls, or trivia.

## Build a mental model

Start with the smallest complete explanation that lets the learner reason about the target. Name the main parts and the relationship between them.

Use this progression:

1. State the practical purpose.
2. Define the concept in ordinary language.
3. Show one concrete mechanism, example, trace, or figure.
4. Ask for a prediction before revealing the result.
5. Work one representative example.
6. Give guided practice with immediate feedback.
7. Remove support for independent practice.
8. Ask for retrieval after a delay.
9. Test transfer in a different context.

Label a teaching simplification. State the omitted detail when it could affect later reasoning.

## Use prediction before explanation

Prediction makes the learner commit to a model before seeing the result. Use it when the outcome follows from a mechanism that the lesson intends to teach.

A useful prediction prompt:

- Presents enough information to reason.
- Does not reveal the answer through wording or formatting.
- Requires an answer before the reveal.
- Asks for a short reason when reasoning is part of the objective.
- Compares the prediction with the observed result.
- Explains the mechanism after the reveal.

Do not punish an incorrect prediction. Use it to expose the learner’s current model.

## Use worked examples deliberately

A worked example must expose the reasoning that can transfer to a new problem. Do not show only the final answer.

For each important step, show:

- The local goal.
- The information used.
- The decision or transformation.
- Why the step is valid.
- What would change under a different condition.

After the example, state the reusable reasoning. Then give a near practice item that uses the same structure with different surface details.

## Fade scaffolding

Use support to enable the target performance, then remove it.

A common sequence is:

1. Complete model.
2. Partially completed example.
3. Prompted performance.
4. Hint on request.
5. Independent performance.
6. Transfer performance.

Track the highest level of support used. Do not record independent demonstration when the learner needed the model solution or a hint that supplied the decisive step.

## Use retrieval and spacing

Retrieval practice asks the learner to produce information or a procedure from memory instead of rereading it. Spacing revisits important material after time has passed. Research reviews find that both strategies can improve durable learning across domains and ages, while their effects depend on task, feedback, prior knowledge, and schedule.[^1]

Use retrieval in three time frames:

- Immediate retrieval checks whether the learner can reconstruct the lesson after instruction.
- Delayed retrieval checks whether the capability remains available later.
- Successive relearning combines correct retrieval with later repeated retrieval.

Do not call immediate success retention. Record retention only after a meaningful delay.

Give corrective feedback after retrieval. Avoid repeated unsupported guessing when the learner has no basis for a useful attempt.

## Use interleaving after separate instruction

Interleaving mixes related problem types so the learner must select the correct method. Use it after each method has been introduced clearly on its own.

Interleaving is useful when the objective includes discrimination or method selection. It is not a substitute for initial explanation or blocked practice when a learner is first forming a procedure.

Build interleaved practice with:

- Similar cases that require different methods.
- Different cases that use the same underlying principle.
- A prompt that does not announce which method to use.
- Feedback that explains the selection decision, not only the execution.

## Test transfer

Transfer requires the learner to select and apply the concept in a context that differs from instruction.

Change one or more dimensions:

- Surface details.
- Domain or scenario.
- Representation.
- Available data.
- Tool or environment.
- Problem order.
- Constraints.

Keep the target concept stable. Do not change so many dimensions that the task measures unrelated prerequisites.

A transfer task must require the learner to recognize when the concept applies. If the prompt names the exact method, it may test execution but not selection.

## Correct misconceptions

A misconception is a stable explanatory pattern, not a single accidental mistake.

Before labeling a misconception:

1. Identify the first consequential error.
2. Ask for the learner’s reasoning when appropriate.
3. Check the pattern with a second case.
4. Distinguish conceptual errors from reading, interface, notation, or arithmetic errors.

Correct a misconception by:

1. Naming the incorrect rule or assumption without shaming the learner.
2. Showing a case that the incorrect model cannot explain.
3. Replacing it with the smallest accurate model.
4. Applying the corrected model to the original case.
5. Rechecking with a new case.

## Adapt from evidence

Adapt the next activity from observed performance, not from confidence alone.

| Evidence | Next action |
|---|---|
| Correct with no hints and clear reasoning | Increase independence or test transfer |
| Correct after a small prompt | Give another similar item with less support |
| Correct answer with incorrect reasoning | Correct the model before increasing difficulty |
| Repeated conceptual error | Return to the mechanism or missing prerequisite |
| Interface or formatting error | Fix the delivery problem without lowering conceptual difficulty |
| High confidence and incorrect result | Add calibration and explanation prompts |
| Low confidence and correct independent result | Confirm the evidence and reduce unnecessary support |

Do not infer disability, motivation, identity, or mastery from limited behavior. Record only observed evidence and learner-provided context.

## Maintain learner agency

The learner should know:

- The purpose of the activity.
- What action is required.
- What counts as success.
- Whether the activity is practice or assessment.
- When feedback or an answer becomes available.
- What data is stored or transmitted.

Do not use false urgency, deceptive progress, forced timers, or unnecessary penalties. Allow reset and repeated practice unless repetition would invalidate the assessment.
